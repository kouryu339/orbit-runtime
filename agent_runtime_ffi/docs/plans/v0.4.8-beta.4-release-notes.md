# v0.4.8-beta.4 — Workflow authoring guidance and approval expiry

## Changes since Beta.3

- `thinking-pro` now derives Workflow step numbers recursively from the control-flow tree.
  Its guidance includes a three-level `FOR` / `IF` example, explicit branch-number rules,
  and a mandatory pre-submit numbering audit.
- Workflow argument guidance now classifies every value before submission. Fixed strings,
  including column names such as `"batch_id"`, must be quoted; bare values are limited to
  constants, references and registered Pure expressions. Native-FC over-escaping examples
  are called out explicitly.
- Compile-error recovery now tells the model to rebuild the affected numbering subtree and
  re-audit every fixed string instead of mechanically patching only the reported line.
- The Lit approval shelf now removes terminal permission requests when Runtime reports
  `resolved: false` or publishes `tool:permission-resolved`. A delayed or missed snapshot no
  longer leaves an expired approval card that cannot be dismissed. Non-terminal policy
  rejection remains visible and retryable.

## Host integration

- ABI remains 1.3. Update the native binary and SDK release metadata together and verify the
  published SHA256 checksum.
- Restart Runtime and create a new conversation after updating so the embedded `thinking-pro`
  text is used by the model. Existing conversation context is not rewritten retroactively.
- Hosts using the bundled Lit package must update its generated `dist` files as well as the
  native Runtime. Native archives alone do not replace a separately bundled frontend.
- Custom frontends should treat `tool:permission-resolved` as terminal for the matching
  `tool_call_id` and remove its approval UI. A permission response with `resolved: false`
  likewise means the request has already expired or otherwise left the pending set.
- Keep ordinary transport or policy rejection visible unless Runtime identifies the request as
  terminal. Do not remove unrelated concurrent approvals.
- Workflow scripts remain compiler-strict. This release improves model-side prevention and Lit
  state convergence; it does not silently quote values, renumber scripts, or mutate host RPC
  requests. Hosts may add their own preflight without changing the Runtime protocol.

## Distribution

Windows x86_64 and Linux x86_64 native archives; no macOS binary. This is a prerelease,
published from `jiangrong/native-fc-core`, not main. Linux cross-build/package verification
does not by itself certify Linux dynamic loading or live host integration.
