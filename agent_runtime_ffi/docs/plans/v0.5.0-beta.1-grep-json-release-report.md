# v0.5.0-beta.1 GrepJson 更新与发布核验

- 仓库：https://github.com/kouryu339/orbit-runtime
- 分支：jiangrong/multimodal-model-support
- 发布：覆盖现有 v0.5.0-beta.1 预发布，不合入 main；稳定版保持 v0.4.8。
- 发布附件：Windows/Linux x86_64 原生库 ZIP 及各自 SHA-256 文件。

## 修改范围

- GrepJson 提供 outline、search、read、page；与 Grep 共用宿主授权根、可读配置和并发/时间/文件/输出限制。
- 返回准确 JSON Pointer、父级及祖先标识、完整值或明确的不完整标记、继续读取位置、原始文件 SHA-256 revision。
- 分页非零 offset 必须提供 expected_revision；文件变化返回 409，宿主修改工具在写锁内重新校验版本并原子写入。
- 保留合法特殊字段名、超大整数、高精度数值及 Unicode；重复字段、错误语法和过深 JSON 明确拒绝。
- 小对象整体留到下一页，避免因页尾空间不足造成额外子树读取。
- thinking/thinking-pro 默认不开放 GetSkillsList、UpdateSkills、Grep、GrepJson；工具实现仍可由宿主自己的 Skill 显式提供。HistoryRead 保留。
- 包含此前已提交的 Lit 控件边框、背景、悬停和选中颜色优化。
- 新增中英文 GrepJson 契约，更新 SDK 原生包哈希及发布说明。

## 验证

- Rust 格式检查及工作区串行测试通过；GrepJson 19 项单元测试、2 项集成验收通过。
- 2,360,802 字节场景文件完整恢复 256 个关键帧，分页相关调用从 12 降至 8；修改后旧 revision 拒绝，重新定位正确。
- Lit 类型检查、74 项测试、构建通过；Go SDK 检查、C++17 示例语法编译及 Python SDK 元数据检查通过。
- Windows/Linux ZIP 内库文件、头文件与构建产物一致，哈希与所有 SDK 元数据一致。
- Windows DLL 加载、版本 0.5.0-beta.1、ABI 1.3、公开注册接口、启动、工具目录读取、关闭及销毁验证通过；GrepJson 的 10 个参数、只读属性、非工作流属性正确。
- Linux x86_64 交叉编译、链接、ELF 格式与压缩包检查通过；未执行 Linux 动态加载。
- 发布后核对开发分支、Beta 标签、四个附件的 SHA-256 与预发布状态；main 和 Latest 稳定版本应保持原值。

## 宿主接入

1. 刷新旧 Beta.1 下载缓存，替换原生库和本次 SDK 元数据后重启。
2. 根据需要在宿主自定义 Skill 中提供 Grep 和/或 GrepJson；AI 技能激活同样由宿主选择。
3. 在资源注册的 grep 配置中声明可读根。默认单文件上限 2 MiB，读取更大的 JSON 时按实际业务显式提高该上限与节点限制。
4. 保留 existing host 修改工具；读取后携带 revision 与 pointer，修改时在与所有写入方共享的写锁中校验 revision、Schema 并原子持久化。

## Engineering Review

Architecture: 结构化只读工具复用 Grep 授权与资源边界；写入、业务 Schema 与 Skill 激活属于宿主。
Code: 单次解析明确区分对象与数值；分页统一输出完整 JSON、完整性标记和继续位置。
Concurrency: 与 Grep 共用并发限流，阻塞任务持有许可至结束；版本校验防止跨版本分页，宿主负责读改写的同步。
Resource: 文件、输出、节点、深度、执行时间均受限；不建立常驻文档缓存。
Audit: 返回原始文件 revision、定位路径、状态与错误；原生包和 SDK 有可核对的哈希。
Verification: 工作区、工具验收、Lit、SDK、Windows 运行检查和双平台包检查通过；远程发布另行实时核验。

Risks: Linux 动态加载未验证；同版本替换需刷新缓存；原始字节 SHA-256 会因空白变化而失效，这是预期行为。
Decisions Needed: 无。
