# v0.4.8-beta.5 — Direct RPC array arguments

## Changes since Beta.4

- Restore native function-call JSON arrays for directly invoked RPC tools according to their declared parameter types, including `Array<Number>` and `Array<Any>`.
- Preserve empty arrays and reject non-array JSON for array parameters before dispatching to the host. Existing `Array<String>` comma-separated input remains supported.
- Add regression tests for the native-FC projection and RPC argument conversion paths.

## Host integration

- ABI remains 1.3. Update the native Runtime binary and SDK release metadata together, and verify the published SHA256 checksum.
- The host does not need to change its array declarations or Excel tool handlers. Direct AI calls to RPC tools declaring array inputs now receive JSON arrays instead of strings.
- Restart Runtime after replacing its native binary. Existing workflow-internal tool execution was not changed by this fix.
- This release does not correct invalid workflow `GetArrayElement` indices or Excel query syntax such as `==`; those are separate errors.

## Distribution

Windows x86_64 and Linux x86_64 native archives; no macOS binary. This is a prerelease published from `jiangrong/native-fc-core`, not `main`. Linux cross-build/package verification does not by itself certify Linux dynamic loading or live host integration.
