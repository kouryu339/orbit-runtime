# v0.4.8-beta.5 — Direct RPC array arguments

## Changes since Beta.4

- Restore native function-call JSON arrays for directly invoked RPC tools according to their declared parameter types, including `Array<Number>` and `Array<Any>`.
- Preserve empty arrays and reject non-array JSON for array parameters before dispatching to the host. Existing `Array<String>` comma-separated input remains supported.
- Add regression tests for the native-FC projection and RPC argument conversion paths.
- `item()` / `GetArrayElement` now accepts finite, in-range integral numeric values such as `0.0` while continuing to reject fractional indexes. This keeps the Workflow `num` contract consistent with its integer-index requirement.
- `thinking-pro` now requires the built-in `$index` when a `FOR <array>` body reads other position-aligned arrays, and forbids manually incrementing an index with `add()`.
- IF numbering guidance now treats statements indented after IF as true-branch logic and requires both numbering layers: `.1.k` for true and `.0.k` for false. Nested IF branches recursively add both layers without omission.
- `thinking` and `thinking-pro` now stop pursuing a tool path once its required capability is confirmed absent, and `thinking-pro` performs one concise script check instead of repeatedly simulating compilation.
- Workflow compilation reports multiple independent numbering mistakes in one response (up to 64), including the expected number and source position. The AI tool and Runtime return these structured diagnostics; a syntax error that prevents parsing still reports its first blocking error.
- History compaction now truncates tool-result previews on UTF-8 character boundaries, so Chinese and other multibyte text cannot panic the Runtime. Explicit compaction reports model failures or panics and clears the `compacting` state instead of leaving the conversation waiting indefinitely.
- Registered Workflow reference nodes now pass their parent's `workflow_run_id` to the referenced Workflow and its RPC nodes. Parent and child Trace events share one sequence counter, so subscribers can correlate and order the entire run without duplicate sequence numbers.
- FOR bodies now isolate every nested IF/ELIF control-flow tail. Only the loop's `Completed` pin can enter the following top-level step, preventing branch exits from repeating uploads, submissions, or other side effects after individual iterations.
- Workflow validator v2 compares persisted script and blueprint control-flow semantics. Reads mark mismatched resources invalid, and execution checks the selected Workflow plus referenced Workflows before running, so legacy inconsistent graphs fail before producing side effects; resubmit the authoritative script to regenerate the blueprint.
- History compaction now commits recoverable checkpoints that preserve the previous summary contract, complete tool evidence, concurrent head/tail arrivals, and resumable record references instead of relying on a lossy tail rewrite.
- Runtime now supports host-registered Jev execution units: an Agent selects a named Jev with an initial task, Jev chooses only explicitly allowed atomic tools, and every run keeps conversation ownership, state snapshots, permission checks, and host-visible execution events.
- Tool availability is now explicit across Agent, Workflow, and Jev contexts in local and RPC descriptors. Existing `system_only` tools remain AI-only, while `jev_only` can expose a tool solely to Jev selectors.
- The resident Agent tool catalog keeps every active tool callable and retains complete input requirements, but removes repeated output documentation and compresses general-tool usage text. `ToolDescribe` returns the full input/output contract, Workflow pins, schema revision, and descriptor hash on demand.
- Host dynamic snapshots remain available for persistence and state projection but are no longer appended to every model request as a volatile tail message.

## Host integration

- ABI remains 1.3. Update the native Runtime binary and SDK release metadata together, and verify the published SHA256 checksum.
- The host does not need to change its array declarations or Excel tool handlers. Direct AI calls to RPC tools declaring array inputs now receive JSON arrays instead of strings.
- Restart Runtime after replacing its native binary. Start a new conversation if the updated embedded `thinking-pro` guidance must be present in model context; existing conversation context is not rewritten.
- Fractional and out-of-range array indexes remain invalid. Excel query syntax such as `==` remains a separate error.

## Distribution

Windows x86_64 and Linux x86_64 native archives; no macOS binary. This is a prerelease published from `jiangrong/native-fc-core`, not `main`. Linux cross-build/package verification does not by itself certify Linux dynamic loading or live host integration.
