外部 RPC 工具 RPC Tools / Sidecar

PRINCIPLE

三层接入：端点、定义、可见性

REGISTRATION
  • Sidecar 用 SDK 注册工具，AgentToolService.ListTools 返回 ToolDescriptor 列表。一个端点可以提供多个工具。
  • 宿主在 start 前通过 runtime.register_resources 提交 resources.json / rpc_endpoints[]。
  • Runtime 发现并校验定义，注册 RPC stub 与动态节点；role / feature skill 的 tools 再选择 Agent 可见工具。
  • 工具名是稳定能力标识；endpoint id 是路由标识。业务 gRPC 的定义来自 ListTools，不在资源配置中重复内联。

ToolDescriptor：能力契约

METADATA
  • name、description、parameters 描述工具用途和输入；outputs 声明结构化输出字段，也用于 Workflow 引脚。
  • readonly、destructive 描述副作用；idempotent 声明重试特征；open_world、secret 表达外部访问与敏感性。
  • agent_enabled、workflow_enabled、jev_enabled 控制对应入口是否可用；skill 仍负责 Agent 的能力选择。
  • required_capabilities 显式声明所需 HostCall，例如 workspace.resolve_path。声明会在发现与调用阶段检查。

Execute：一次调用，一条双向流

BIDIRECTIONAL STREAM
  • RPC stub 将参数与调用上下文组装成 ExecuteRequest，按 tool_name 分发到端点的 handler。
  • Execute(stream ToolStreamMessage) 同时承载请求、HostCall / HostResult、ToolLog 与最终 AIOutput / ToolError。
  • 首条消息必须是 ExecuteRequest；消息的 call_id 必须对应当前调用。HostCall 还用自己的 id 匹配 HostResult。
  • Rust SDK 优先读取对象形式的 args_json，未提供时才解析 args_cli；结构化参数适合代码、换行和复杂文本。

4

ToolContext：身份随调用传递

PER-CALL CONTEXT
  • call_id 关联 RPC 流；tool_call_id 对应模型工具调用；idempotency_key 供工具实现去重。
  • Agent 来源通常有 conversation_id / agent_id / turn_id；Workflow 来源有 workflow_run_id / node_id，可附带 workflow_id。
  • Agent 发起 Workflow 时两组来源可同时存在；宿主直接执行 Workflow 可没有 Agent 来源，临时 Script 可没有 workflow_id。
  • SDK 还暴露 provider / session、permissions、host_context 等协议字段；工具读取本次 ToolContext，避免从共享全局状态猜身份。

字段是否非空取决于调用入口；协议支持某个字段不代表每次调用都填充它。当前 stub 以 tool_call_id 设置幂等键，去重记录由工具侧维护。

HostCall：受控调用宿主能力

CAPABILITY GATE
  • 工具在执行流中请求 workspace.*；Runtime 检查操作受支持、工具已声明所需能力，然后调用实际 workspace 逻辑。
  • resolve_path / resolve_working_path 为已有文件建立或解析工作副本；create_path / create_working_path 为新文件安排工作路径。
  • save_as_edited 把编辑后的工作文件另存为用户文件；HostResult 通过相同 HostCall id 返回。
  • 当前官方 HostCall 是上述 workspace 操作。旧 snapshot.get / snapshot.put 已移除，动态上下文由宿主单独更新。

6

结果：机器数据与模型摘要

AIOUTPUT
  • 线上的 AIOutput 包含 result_json + to_ai + error_code；SDK 内部 result 使用原生 JSON 值。
  • result_json 供程序消费；to_ai 为下一轮模型说明结果、失败原因和可采取的下一步，SDK 要求非空。
  • 业务失败仍形成 AIOutput；协议异常、未知工具、连接失败等走 ToolError / transport error 路径。
  • Proto 成功码为显式 OK=1，UNSPECIFIED=0 会被拒绝；Runtime 转换后的本地成功码为 0。

普通摘要单项默认上限 600 字符；to_ai_max_chars=0 取消字符限制，数组 / 对象摘要仍最多取 12 项。此限制用于模型摘要，不代表原始 result 一律截断。

三层约束：审批、能力、隔离

EXECUTION BOUNDARY
  • Agent 工具策略：根据工具 effect 选择 full / ask / deny，在执行之前决定是否允许或等待审批。
  • Runtime HostCall：限定协议内的宿主能力及声明；它检查受控回调入口。
  • RPCtools 服务侧：部署方提供的内部 sandbox、资源访问权限与业务授权，约束 handler 实际能操作什么。
  • 通用 RPC SDK 提供协议和能力适配，没有自动创建 OS sandbox。外部进程的文件、网络和 CPU 边界由部署配置落实。

HostCall 检查覆盖经该入口发起的宿主操作。直接文件 / 网络访问需要工具服务侧的实际隔离；宿主直接执行 Workflow 的授权仍由宿主承担。

超时、重试与进程生命周期

FAILURE & LIFECYCLE
  • timeout_ms 包含连接、工具执行和 HostCall 往返。超时结束本地等待，外部操作是否完成需要另行核验。
  • launch.kind=process 可启动进程并在启动窗口内反复探测 ListTools；external 连接外部服务。
  • 启动探测重试不等于 Execute 自动重试；当前 RPC 客户端没有通用执行重试或熔断。
  • ManagedSidecar 负责随运行时生命周期清理子进程；崩溃后的拉起与生产编排由外部 supervisor / 宿主负责。

三类失败，三种处理

FAILURE CONTRACT
情况表现处理依据
参数 / 业务失败AIOutput 非 OK
to_ai 解释原因		补参数、读取状态或修正请求
权限 / HostCall 失败审批拒绝，或
HostResult ok=false		处理拒绝原因，保留当前调用身份
超时 / 断流 / 崩溃transport error
未取得最终输出		核验外部结果，再决定是否重试

idempotent 元数据与 idempotency_key 是实现去重的依据；工具需要实际保存和检查去重记录。超时与本地暂停都不能单独证明外部副作用未发生。

工具作者的最小契约

CONCEPTUAL / SIMPLIFIED
DESCRIPTOR + HANDLER示意，省略语言 SDK 具体语法
descriptor = {
  name: "DescribeDocument",
  parameters: { path: "required string" },
  outputs: { title: "string" },
  readonly: true,
  idempotent: true,
  required_capabilities: ["workspace.resolve_path"]
};

async function handler(ctx, args) {
  validatePathArgument(args.path);
  file = await ctx.workspace_resolve_path(args.path);
  document = await readDocument(file.working_path);
  return {
    result: { title: document.title },
    to_ai: "[成功] 已读取文档标题：" + document.title,
    error_code: ToolErrorCode.Ok
  };
}

工具完成以后：更新谁的状态

RESULT → CONTEXT → UI
TOOL RESULT

报告本次结果

工具返回业务标识、结构化数据与简洁摘要。Workflow 通过声明输出引脚使用结果。

HOST STATE

刷新当前业务现场

宿主读取最新文档 / 页面 / 订单状态，再按 conversation + agent 发布动态文本。

RUNTIME EVENT

投影执行事实

Agent 工具状态由 Runtime 产生；宿主转发给 UI，前端用 call_id 合并工具控件。

conversation.set_dynamic_snapshot 由宿主调用。动态字段恢复后需要重新发布；Jev 的专用结果更新限定在本次 Jev run，保持独立边界。

设计收益

业务服务与 Agent harness 分离。
统一描述可供模型、Workflow 与 UI 使用。
身份和能力声明沿调用链显式传递。

落地责任

工具服务侧 sandbox 与资源权限。
幂等记录、外部结果核验和进程编排。
宿主状态刷新及事件分发持久化。
