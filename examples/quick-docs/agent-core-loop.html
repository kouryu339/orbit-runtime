Agent 核心循环 The Agent Loop

一次输入，驱动多轮推理与工具执行。状态机负责推进，工具结果成为下一轮的依据。

CORE
PRINCIPLE

thinking → executing → thinking 构成工作循环；turn 预算在模型调用前限制思考轮数，token 预算限制单次输入规模。
Harness 管编排、预算与准入，RPCtools 承接工具侧执行边界，业务服务校验实际操作权限。

循环结构

STATE MACHINE
suspended→thinking⇄executing

一轮 thinking 做什么

THINKING
  • 检查轮数预算，通过后汇总角色、激活技能、工具定义、历史与动态上下文。
  • 按 token 输入预算压缩历史，并对最终请求复查；满足预算后调用 LLM Gateway。
  • 原生 tool_calls 与兼容 EXEC 路径分别解析，形成待执行工具批次。
  • 普通回复进入 saying；协议无效、空响应及请求失败走相应纠正或错误处理。

thinking 是一次状态进入；内部可能包含模型请求重试，历史压缩也可能调用摘要模型。因此，思考轮数与 HTTP 请求总数是不同口径。

Turn 预算：模型调用前检查

PRE-REQUEST ROUND LIMIT
0默认不启用轮数上限 · 由宿主显式配置
  • 宿主通过 max_thinking_rounds 设置上限；thinking 入口先执行 round++，再判断正数上限是否被超过。
  • 超限就本地收敛，不发起本轮 LLM 请求。通过检查后，才继续组装上下文与调用模型。
  • 默认 0 跳过轮数限制。一次响应里的多个工具调用不分别扣轮数；工具批次完成、再次进入 thinking 时才增加下一轮。
例：max_thinking_rounds = 2
第 1 轮检查通过 → 调模型
第 2 轮检查通过 → 调模型
第 3 次进入超限 → 本地停止

常规无重试路径：最多 2 次主模型调用。

轮数在 saying 中重置；单轮内部的重试不会额外增加轮数。

Token 预算：这次请求能装多少

CONTEXT BUDGET
90%模型上下文窗口 → 自动输入预算
input_budget = floor(context_window × 90%)
history_budget = max(input_budget − fixed_context, 0)
  • 固定开销含系统提示、工具定义、动态上下文和 128 token 余量；余下空间留给历史。
  • 历史估算超预算，或消息数超过上限（默认 200 条），先尝试压缩完整执行组并保留最新用户请求。
  • 组装最终请求后再次估算；固定上下文过大，或安全压缩后仍超预算，则返回错误并保留原始 ledger，不发送该请求。
三种 token 口径
口径当前行为
单次输入本地按 90% 上下文窗口估算、压缩并复查。
单次输出thinking 当前未显式传入 max_tokens；实际输出约束取决于下游配置与服务端。
累计消耗ai:llm-usage 记录输入、输出与缓存用量；主循环未设置跨轮累计 token 硬限额。

当前 token 数为保守估算，包含协议字段，并非 provider 精确 tokenizer；usage 是模型返回的用量口径。

5

工具执行与结果回灌

EXECUTING
  • 先授权，再执行。校验 Agent 可调用性、激活工具与参数，分派到已注册的 local / RPC 工具。
  • 本批工具由 JoinSet 并发调度；收齐后按原调用顺序整理结果。
  • 原生 FC 保留 assistant(tool_calls) 与对应的 tool_call_id，结果写入 ledger。
  • 完成批次后通常回到 thinking，让模型依据真实结果继续决策。

并发调度不等于业务互斥；共享数据写入与幂等由工具服务保障。

权限与人工审批

POLICY GATE
  • 工具按元数据分为只读、受控修改、破坏性操作。
  • Ask 创建待审批请求，宿主用会话 ID 和调用 ID 返回决定；等待上限 300 秒。
  • 拒绝、超时或取消均形成工具结果，不执行该调用。
Full直接执行
Ask等待审批
Deny拒绝执行

当前默认策略三类均为 Full；宿主应按场景显式配置。审批本身不提供操作系统隔离。

暂停、压缩与恢复

CONTROL & CONTEXT
  • 每轮请求前检查历史预算；压缩采用准备、提交的分离过程。
  • 默认 wait_for_tool 等当前 LLM / 压缩 / 工具收尾后暂停；detach_tool 停止本地等待。
  • 工具被 detach 时，外部副作用可能仍然发生；以 interrupted_unknown 表示不确定结果。
  • 不确定调用不能自动当作失败重试。先核对外部状态与幂等条件，再决定恢复动作。查看暂停与恢复详解 →

停止与多 Agent 协作

SAYING → SUSPENDED
  • saying 发布用户可见回复；等待输入时发出 TURN_DONE，通常转入 suspended。
  • 暂停与等待是停靠状态；下一次输入或恢复事件可重新启动循环。
  • 委派任务的候选结果先进入 reported；由委托方接受、修订要求或取消。
  • 回复结束、Agent 停驻、委派任务完成是不同的状态。

核心循环伪代码

CONCEPTUAL / SIMPLIFIED
STATE DRIVER省略协议兼容、暂停与错误分支
async function drive(input) {
  await admitAndRecord(input);
  state = "thinking";

  while (state !== "suspended") {
    if (state === "thinking") {
      round++; // 一次 thinking 入口记一轮
      if (maxRounds > 0 && round > maxRounds) {
        state = prepareFallbackReply(); // → saying
        continue;
      }
      inputBudget = floor(contextWindow * 0.9);
      messages = await prepareAndCompact(inputBudget);
      // 包含系统提示、工具定义、动态上下文和历史
      if (estimateInput(messages, tools) > inputBudget)
        throw "ContextBudgetExceeded";

      response = await callModel(messages, tools);
      await recordUsage(response); // 记账 ≠ 累计熔断
      if (hasToolCalls(response)) {
        await saveAssistantAndPendingCalls(response);
        state = "executing";
      } else state = prepareReply(response);
    } else if (state === "executing") {
      // 每个调用独立授权；拒绝也返回工具结果
      results = await runToolBatch(pendingCalls, {
        authorize: permissionPolicy,
        execute: registeredLocalOrRpcTool
      });
      await appendOrderedResults(results); // FC 配对
      state = "thinking";
    } else if (state === "saying") {
      await publishReplyAndTurnDone();
      round = 0;
      state = "suspended";
    }
  }
}

三层边界，各自负责

DEFENSE IN DEPTH
LAYER 01

Harness

状态推进、模型调用前的轮数与上下文预算、工具准入、审批及记账。

LAYER 02

RPCtools

参数校验、执行隔离；按部署限制文件、网络与进程。

LAYER 03

业务服务

身份、租户、数据范围、业务规则与幂等。

工具侧 sandbox 为本页采用的部署前提，不代表 RPC 协议或 Runtime 自动提供隔离；local 工具路径需独立约束。

WHY THIS SHAPE

清晰的职责

前置轮数预算控制继续，上下文预算控制输入。
ledger 与事件保留执行事实和用量。
审批与工具执行隔离分层配置。

需要守住的约束

中断后先确认副作用，再决定重试。
