暂停当前推进，保留已发生的事实。继续时重新思考，重建时依据 ledger 判断安全入口。

PRINCIPLE

暂停受理 → stopping → 安全边界收敛 → suspended。默认等待在途工作完成；detach 停止本地等待。
原会话继续由新输入 / 内部唤醒驱动；快照恢复重建执行状态，外部资源与未知副作用仍需核对。

1

先区分三个动作

THREE OPERATIONS
  • 暂停：进程与会话还在，让当前 Agent 停止推进并停靠到 suspended。
  • 继续：在现有会话内接受新用户消息或内部唤醒，保留已记录的历史，再进入 thinking。
  • 快照恢复：进程重启或迁移后，从持久化 ledger / state 重建会话和 Agent 实例。

conversation.close 结束并移除会话；Runtime shutdown 关闭整个运行时。两者都不等同于暂停。

agent/runtime.rs · runtime/conversation_operations.rs · recovery.rs

2

默认暂停：等当前工作收尾

WAIT_FOR_TOOL
wait_for_tool 默认模式
  • LLM 已在途：等待这次模型请求完成，期间不取消当前请求；返回后不启动响应里的工具调用。
  • 历史压缩在途：允许当前摘要工作收尾，再在边界消费暂停信号。
  • 工具批次已在途：等待本批完成，记录结果后停驻，不进入下一轮模型调用。
  • 请求尚未登记：阻止新请求发出；两种暂停模式都覆盖这个窗口。

名称保留了 tool，但控制范围包含 LLM 与压缩；默认暂停并不保证立刻进入等待状态。

AgentExecutionControl::request_thinking_pause · AgentRuntime::pause_with_mode

3

快速暂停：停止本地等待

DETACH_TOOL
detach_tool 主动退出等待
  • LLM 在途：取消本地等待，丢弃迟到响应和未处理的流式数据；已展示文字保留。
  • 工具在途：终止本地任务的等待与收集；已收到的结果保留，缺失结果补为 interrupted_unknown。
  • 该标记表示成功、失败或仍在执行均有可能；不能据此自动重复调用。
  • 外部 RPC / 服务端可能继续执行。本地任务退出没有撤销外部副作用的保证。

state/thinking.rs · executing.rs::run_tools · interrupted_unknown_tool_result

4

已受理与已停驻

OBSERVE THE STATE
accepted→stopping→suspended
  • 命令先经过 admission；accepted 表示获准，不表示工作已经停下。
  • stopping 是前端投影中的“正在暂停”；压缩时也可能继续显示 compacting。
  • Agent 消费暂停信号后写入 task_status=paused、last_stop_reason=pause，清理待执行及路由字段。
  • Agent 最终停到 suspended；会话聚合投影需按实际实例状态判断，不能只看按钮或 admission 返回。

conversation.pause 路由到当前 focus Agent；后台 worker 不应被理解为同时全部暂停。

gateway.rs::request_pause_with_admission · state/mod.rs · snapshot.rs

5

未执行与结果未知，要分开

KEEP THE FACTS
  • cancelled_before_execution：有完整 FC 声明，但工具尚未启动；以原 tool_call_id 写入 role:tool，标记 executed:false。
  • interrupted_unknown：工具已脱离，Runtime 未观察到确定结果；外部效果需另行核对。
  • 不完整流式工具调用不写成正式 FC；快照恢复丢弃临时 assistant_stream，不重放部分参数。
  • 已闭合的成功、失败、取消和不确定结果保持终态，不因恢复而重新打开。

state/mod.rs::close_unexecuted_calls · persist_paused_native_response · recovery contract

6

原会话如何继续

RESUME IN MEMORY
  • 宿主用 conversation.send_message 发送新的用户消息；内部调度可通过 RESUME 唤醒。
  • driver 清除旧暂停控制，离开 suspended；状态退出时关闭 waiting 标记。
  • 新一轮 thinking 使用已有历史和最新输入，重新检查轮数与上下文预算。
  • 已取消的旧请求不会复活。重新生成与工具执行都属于后续新工作；未知结果先查验。

这里的 RESUME 是内部状态事件，本页不把它写成不存在的 conversation.resume 宿主命令。暂停中的委派任务更新可以先入账而不自动唤醒。

暂停发生在哪个阶段

BEHAVIOR MATRIX
当前阶段wait_for_tooldetach_tool
LLM 尚未登记阻止新请求阻止新请求
LLM / 摘要在途等待当前工作收尾；不再开启后续工作取消本地等待；迟到响应丢弃
完整 FC 未执行补 cancelled_before_execution 配对结果未执行的正式声明闭合；被丢弃的未持久化响应不补成正式调用
工具批次在途收齐本批结果后停驻保留已知结果；缺失结果标记 interrupted_unknown
已经 suspended保持停驻；继续需要新输入或对应唤醒调度

LLM 的本地取消不等于 provider 停止计算；工具脱离也不等于业务回滚。

9

快照恢复：先重建，再继续

DURABLE RECOVERY
01

先注册当前配置

加载 cluster / Agent definition、模型、技能与工具。权限以当前注册表为准，快照不能覆盖注册定义。

02

导入可恢复快照

使用 conversation.spawn_from_snapshot，或向指定会话 import_snapshot；输入为 agent-runtime-conversation-snapshot/v1。

03

恢复协议与执行入口

先应用 tool_protocols，再解析 ledger 和任务榜，重建 thinking / executing / suspended。临时流式数据不重放。

04

核对外部环境后推进

宿主重新绑定业务对象、RPC session、文件或浏览器资源，发布最新动态状态，并核验不确定副作用。

UI 快照不等于恢复检查点。手动稳定导出默认要求会话聚合为 waiting；持续持久化 ledger / state 增量才能覆盖意外崩溃。恢复也不是把旧进程的调用栈原样接回。

10

Ledger 尾部决定恢复行为

SAFE REPLAY
已持久化的最后事实重建入口 / 后续处理
用户消息尚未处理thinking：准备继续处理用户意图。
干净 assistant 回复suspended：保留已完成回复，等待输入。
FC 声明，无 startedexecuting：可接续未开始的工具调用。
started，无终态，只读executing：允许重新观察 / 查询。
started，无终态，写入或未知executing：用原 call id 生成恢复不确定结果，不直接重跑真实工具。
工具结果已经闭合thinking：使用结果继续；该调用终态不重新打开。

恢复入口由核心运行时从 ledger 推导；恢复到 thinking / suspended 的重建阶段不主动发起新的模型请求，后续由 driver 推进。

宿主操作与观察

CONCEPTUAL / SIMPLIFIED
COMMANDS + DURABLE EVENTS伪代码 · 观察与调度由宿主实现
// 1. 请求暂停；admission 不是停止完成通知
decision = await invoke("conversation.pause", {
  conversation_id: id, mode: "wait_for_tool"
});
if (accepted(decision))
  await observeTargetParked(id); // 宿主观察状态

// 2. 原会话继续：发送新消息
await invoke("conversation.send_message", {
  conversation_id: id, content: "继续处理，并先核对外部结果"
});

// 3. 进程重启后：先准备注册表与外部资源
await prepareCurrentRegistryAndBindings();
restored = await invoke("conversation.spawn_from_snapshot", {
  spawn: { cluster_id: clusterId },
  snapshot: durableConversationSnapshot
});
await rebindAndReconcileBeforeFurtherWork(restored);

// 持续保存；按 record_id / delta 版本幂等处理
onEvent("conversation.ledger_delta", persistLedger);
onEvent("conversation.state_delta", persistState);
onEvent("frontend:state_snapshot", renderUI);

谁负责恢复什么

RESPONSIBILITY

Runtime

按 Agent 管理暂停 token 与执行边界。
保留 FC 配对、完成事实与不确定结果。
根据 ledger 重建入口和待处理调用。

宿主

持续持久化增量，观察实际停驻状态。
重建注册表、外部绑定与媒体资源。
核验业务结果、幂等条件和重试策略。

THE RULE
IN ONE LINE

请求暂停 → 观察收敛 → 保留执行事实 → 恢复上下文与外部绑定 → 查验未知结果 → 再继续。

本页为实现导读；暂停面向当前 focus Agent，内部 RESUME 与宿主命令分开。示例省略错误处理，快照恢复不保证外部事务、进程或 RPC 调用仍在原状态。
