3

引脚：把顺序与数值分开

EXEC + DATA
  • Exec 引脚：表示“接下来走哪条路径”。分支、循环、顺序执行都通过它组织。
  • Data 引脚：表示“这个输入值从哪里来”。连接、默认值与变量共同形成节点输入。
  • Pin 声明方向与类型，Connection 连接具体节点实例的输入 / 输出引脚。
  • Wildcard 表达泛型约束，编译 / 装配时推导具体类型；数组和可选值也有对应容器语义。

数据依赖应保持无环；控制流允许循环。不能把含 Branch / ForLoop 的完整程序一概描述为普通 DAG。

编译：让错误停在运行之前

COMPILE & LOAD
  • Script 解析为结构化步骤并生成 Blueprint；图源经过节点、引脚与连接检查。
  • 结合注册元数据校验类型、数据引用、变量与输出字段；不允许凭空引用工具输出。
  • 加载器装配节点、默认值、连接、稳定 node id 与 source map，形成 CompiledBlueprint。
  • 诊断携带源码行列、错误类别和建议；编译通过只说明程序可建立，业务执行仍可能失败。

上下文：一份程序，多次运行

PER-RUN CONTEXT
  • WorkflowsModule 的执行入口为每次 Run 创建独立缓存，节点引脚与变量不写入模块共享缓存。
  • ExecutionContext 扩展基础 Context，承载局部栈帧、节点状态、执行流与本次 Trace。
  • ExecutionFlow 跟踪节点位置与步数，默认最大 10,000 步；它与 Agent thinking 轮数预算独立。
  • 执行时冻结本次引用的工作流定义；运行身份通过本次上下文传给节点和 RPC。

运行缓存隔离不等于外部数据库或服务事务隔离；工具侧的锁、幂等和并发写入仍需独立保证。

执行器：解释图，推进路径

EXECUTOR
  • 从入口开始，先收集节点输入；缺少纯节点数据时递归求值相应依赖。
  • 将结果写回本次执行缓存，再读取 NodeOutput 决定后续路径。
  • ExecPin / Multiple 选择一个或多个出口；Loop / Break / Complete 表达循环、中断与结束。
  • End 汇集声明的输出；执行错误沿调用链返回。多个出口按现有路径依次推进，不等于自动并行。

工具适配：能力仍在系统侧

CAPABILITY ADAPTER
  • 动态工具节点将数据引脚转为工具参数，经已注册的 local / RPC 能力执行。
  • 工具注册 schema 决定引脚。传输层 result / to_ai / error_code 与图上的业务输出分开。
  • 例如工具声明 page_id、url，图中就连接这两个输出；不存在自动生成的万能 Result 引脚。
  • RPCtools sandbox 与业务授权约束外部执行；工作流引擎本身不因“图执行”而拥有隔离能力。

身份与审计：每次执行可定位

TRACE & IDENTITY
  • workflow_id 标识资源，run_id 标识一次运行；临时脚本可以没有资源 id。
  • node_id 对应图上节点；同一节点在循环中每次调用有新的 execution_id。
  • Trace 通过 sequence 排序，通过 parent execution 关联分支、循环和嵌套作用域。
  • Workflow 使用独立公共事件线；不自动进入 Conversation ledger。宿主负责订阅、持久化及画布映射。

执行一次节点：抽象伪代码

CONCEPTUAL / SIMPLIFIED
GRAPH INTERPRETATION省略缓存策略、嵌套循环与 Trace 细节
async function run(definition, inputs, origin) {
  graph = compileAndLoad(definition, nodeRegistry);
  ctx = newRunContext(inputs, origin); // 独立现场
  await visit(graph.entry, ctx);
  return collectEndOutputs(ctx);
}

async function visit(node, ctx) {
  checkExecutionStepLimit(ctx);
  values = await collectInputs(node, ctx);
  // 数据来源：连接 / 默认值 / 变量
  // 纯计算依赖按输入需求求值
  bindCurrentNodeIdentity(node, ctx);
  output = await node.execute_node(ctx, values);
  storeOutputsAndRecordFacts(node, output, ctx);

  switch (output.kind) {
    case "ExecPin": return await follow(output.pin);
    case "Multiple": return await followInOrder(output.pins);
    case "Loop": return await runLoopBody(output, ctx);
    case "Data": return output.values;
    case "Break": return BREAK_CURRENT_LOOP;
    case "Complete": return;
  }
}

边界：引擎、Agent 与宿主

RESPONSIBILITY
AGENT

决定是否调用

AI 工具入口按 destructive 策略审批；来源身份随本次调用传入。

ENGINE

按已定义图执行

编译、参数与引脚校验、运行隔离、控制流、输出与 Trace。

HOST / TOOLS

管理外部事实

鉴权、sandbox、业务幂等、事务、持久化及跨进程协调。

宿主直接调用 workflow.execute 是直接执行；携带 conversation / agent 身份不自动触发 Conversation 审批。两项来源身份须成对提供。

清晰的设计收益

同一节点契约服务编辑、编译与执行。
定义可复用，每次 Run 独立保存执行态。
控制与数据显式连线，故障可定位到节点。

实际实现边界

保留兼容模块，不能把旧 trait 当成新主接口。
执行步数限制不提供事务回滚或自动重试。
Trace 事件由宿主保存，不是耐久调度日志。
